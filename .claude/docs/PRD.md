# PRD: Acorn Collector (행사용 도토리 주머니)

> 덕질 행사/전시회에서 방문할 부스와 구매할 상품을 관리하는 브라우저 확장 프로그램

## 1. Overview

### 1.1 Problem Statement

덕질 행사(동인 행사, 전시회, 굿즈 판매 이벤트 등)에 참여할 때:
- 트위터(X)에서 여러 서클의 홍보글을 보며 "이 부스 가야지" 하고 기억에만 의존
- 선입금 상품 수령, 현장 구매 예정 상품 등을 체계적으로 정리하기 어려움
- 행사 당일 어떤 부스를 돌았는지, 뭘 샀는지 트래킹이 안 됨
- 부스 배치도를 보며 동선을 계획하기 어려움

### 1.2 Solution

브라우저 확장 프로그램으로:
1. **트위터/웹페이지에서 바로 부스 정보 저장** - 버튼 클릭 시 텍스트/이미지 파싱
2. **체크리스트로 관리** - 부스별 구매 예정 상품, 체크 여부
3. **이미지로 내보내기** - 행사 당일 오프라인 참고용
4. **(고도화) 동선 표시** - 부스 배치도에 방문 순서 그리기

### 1.3 Target Users

- 동인 행사 참가자 (코믹월드, 서코, 일러스타 등)
- 전시회/팝업스토어 방문자
- 굿즈 덕질러 (K-pop, 애니메이션, 게임 등)

## 2. User Stories

### 2.1 Core User Flow

```
[트위터에서 홍보글 발견]
    ↓
[확장 아이콘 클릭 or 우클릭 → "부스 체커에 추가"]
    ↓
[자동 파싱 시도 → 부스번호, 서클명, 상품 정보 추출]
    ↓
[파싱 결과 확인/수정 → 저장]
    ↓
[확장 팝업에서 체크리스트 관리]
    ↓
[이미지로 내보내기 → 행사 당일 사용]
```

### 2.2 User Stories

| ID | As a... | I want to... | So that... |
|----|---------|--------------|------------|
| US-01 | 행사 참가자 | 트위터 홍보글에서 버튼 하나로 부스 정보를 저장 | 여러 탭을 오가며 수동 정리하지 않아도 됨 |
| US-02 | 행사 참가자 | 파싱 실패 시 수동으로 정보를 입력 | 어떤 형식의 홍보글도 저장 가능 |
| US-03 | 행사 참가자 | 이벤트별로 부스 목록을 분리 관리 | 여러 행사를 동시에 준비 가능 |
| US-04 | 행사 참가자 | 부스별 구매 예정 상품을 체크리스트로 관리 | 행사 당일 빠뜨리지 않고 구매 가능 |
| US-05 | 행사 참가자 | 체크리스트를 이미지로 내보내기 | 오프라인/모바일에서 참고 가능 |
| US-06 | 행사 참가자 | 선입금 상품과 현장 구매 상품을 구분 | 수령/구매 여부를 명확히 트래킹 |
| US-07 | 행사 참가자 | 부스 배치도에 동선을 그려서 저장 | 효율적인 동선 계획 (고도화) |

## 3. Functional Requirements

### 3.1 MVP (v1.0)

#### 3.1.1 부스 정보 수집

| ID | Requirement | Priority |
|----|-------------|----------|
| FR-01 | 현재 페이지에서 선택한 텍스트/이미지를 파싱하여 부스 정보 추출 | P0 |
| FR-02 | 파싱 실패 시 수동 입력 폼 제공 | P0 |
| FR-03 | 우클릭 컨텍스트 메뉴 "부스 체커에 추가" | P0 |
| FR-04 | 확장 아이콘 클릭 시 현재 페이지 분석 및 추가 UI | P1 |

**파싱 대상 정보:**
- 부스 번호 (예: A-01, 홀1-B32)
- 서클/작가명
- 원본 URL

> ⚠️ **상품은 파싱하지 않음**: 사용자가 무엇을 샀는지/살 예정인지는 본인만 알 수 있고, 품목 종류가 너무 다양하여 자동 파싱의 실효성이 낮음. 상품은 사용자가 직접 추가.

**파싱 전략:**
- 텍스트: 정규식 + 휴리스틱 (부스 번호 패턴 인식)
- 이미지: Vision AI API (OpenAI/Claude) 또는 사용자 수동 입력 fallback

#### 3.1.2 데이터 관리

| ID | Requirement | Priority |

| FR-07 | 상품 항목 생성/수정/삭제 (사용자 직접 입력) | P0 |

## 5. Data Model

```
Event (이벤트/행사)
├── id: string (UUID)
├── name: string ("서코 45회")
├── date: string | null ("2026-02-15")
├── location: string | null ("코엑스")
├── mapImageUrl: string | null (배치도 이미지)
├── createdAt: timestamp
└── updatedAt: timestamp

Booth (부스)
├── id: string (UUID)
├── eventId: string (FK → Event)
├── boothNumber: string ("A-01")
├── circleName: string ("서클명")
├── sourceUrl: string | null (원본 트윗/페이지 URL)
├── memo: string | null
├── order: number (정렬용)
├── createdAt: timestamp
└── updatedAt: timestamp

Item (상품) - 사용자 직접 입력
├── id: string (UUID)
├── boothId: string (FK → Booth)
├── name: string ("아크릴 키링")
├── price: number | null (3000)
├── badgeId: string (FK → Badge, 기본값: "purchase")
├── checked: boolean
├── quantity: number (기본 1)
└── createdAt: timestamp

Badge (뱃지/말머리)
├── id: string (UUID or preset key)
├── label: string ("구매", "수령", "기타", 또는 커스텀)
├── isPreset: boolean (기본 뱃지 여부)
├── color: string | null (커스텀 뱃지 색상)
└── createdAt: timestamp

**기본 뱃지 (Preset):**
- "purchase" → "구매" (현장 구매 예정)
- "pickup" → "수령" (선입금 상품 수령)
- "etc" → "기타"
```

## Appendix A: 트위터 홍보글 파싱 예시

**입력 (트위터 텍스트):**
```
[서코45/A-01] 서클명입니다!
판매 품목:
- 아크릴 키링 3,000원
- 포스터 세트 12,000원
- 엽서 세트 2,000원
많관부!
```

**파싱 결과:**
```json
{
  "eventHint": "서코45",
  "boothNumber": "A-01",
  "circleName": "서클명입니다"
}
```

> 💡 상품 정보는 파싱하지 않음. 사용자가 부스 저장 후 직접 추가.

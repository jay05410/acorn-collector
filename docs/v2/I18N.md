# 다국어(i18n) 구조와 언어 추가 방법

기준일 2026-09-29 (ACORN-9). 소유자 결정: 지금은 **한국어(ko), 영어(en), 일본어(ja), 중국어 간체(zh-CN), 중국어 번체(zh-TW)** 다섯 언어만 출시한다. 대신 언어를 나중에 싸고 안전하게 추가할 수 있게 만든다. 다른 언어 번역은 넣지 않는다.

## 1. 한눈에 보기

| 무엇 | 어디 |
|---|---|
| 지원 언어와 언어별 정보(계약 파일) | `src/i18n/languages.ts` |
| 앱 문자열 | `src/i18n/locales/<lang>/<namespace>.ts` + `index.ts` |
| 타입 계약 | `src/i18n/define.ts` (`LocaleMessages`) |
| 지연 로딩 | `src/i18n/registry.ts`(찾기), `src/i18n/catalog.ts`(캐시), `src/i18n/state.ts`(현재 언어) |
| 진입점 | `import { t, tp, tn, useLanguage, formatPrice, formatDate } from '@/i18n'` |
| Chrome 문자열(확장 이름, 메뉴, 단축키) | `src/public/_locales/<chromeLocale>/messages.json` |
| 도구 | `pnpm i18n:export`, `i18n:import`, `i18n:check`, `i18n:new` (`scripts/i18n/`) |

## 2. 구조

### 2.1 언어 레지스트리 (`languages.ts`)

- `APP_LANGUAGES`: 출시하는(켜진) 언어만. 여기 있는 언어는 모두 완전해야 한다(타입 + `i18n:check`). 설정 화면의 언어 선택지도 이 목록 그대로이며 `nativeName`으로 표시한다.
- `LANGUAGE_INFO[lang]`: 언어별 데이터. 앱의 다른 코드는 언어 코드로 분기하지 않고 이 값만 읽는다.

  | 필드 | 쓰는 곳 |
  |---|---|
  | `nativeName` | 언어 선택지 이름 |
  | `englishName` | AI 프롬프트의 번역 대상 언어 (`lib/ai/prompt.ts`) |
  | `intlLocale` | `formatPrice`·`formatDate`·숫자 서식, `Intl.PluralRules`, `<html lang>` |
  | `chromeLocale` | `public/_locales/<chromeLocale>` 폴더 이름 |
  | `defaultCurrency` | 통화가 없는 가격의 기본 통화 |
  | `dayPickerLocale` | 달력 로케일 (`components/ui/day-picker-locales.ts`의 키) |

- `FALLBACK_LANGUAGE = 'en'`: 키의 기준이자 키별 폴백.
- `DRAFT_LANGUAGE_INFO`: 번역 중인 언어(`i18n:new`가 추가). 앱은 이 목록을 읽지 않는다. 선택지·브라우저 언어 감지·로딩 어디에도 나타나지 않는다.
- `detectLanguage(navigator.language)`: 정확히 일치하는 코드 → 중국어는 스크립트/지역(`Hant`, `TW`, `HK`, `MO` → zh-TW, 그 밖 → zh-CN) → 기본 언어 → 영어 순.
- 저장된 설정의 언어가 더 이상 출시되지 않는 코드(예: 한때 목록에 있던 th, fr)면 `migrateSettings`가 브라우저 언어로 다시 감지한다.

`scripts/i18n` 도구는 TypeScript 컴파일러 없이 이 파일을 읽는다. 표는 평범한 리터럴로 둔다(문자열 값, 계산된 키·스프레드 금지). 도구 테스트가 도구가 읽은 값과 실제 모듈 값을 비교한다.

### 2.2 로케일 폴더

```
src/i18n/locales/
  en/            기준 언어. 키 집합의 원본, 사이드패널 번들에 포함
    common.ts    export default { save: 'Save', ... } satisfies MessageTable;
    index.ts     모든 네임스페이스를 모음
  ja/
    common.ts    export default { save: '保存', ... } satisfies LocaleMessages['common'];
    index.ts     export default { ... } satisfies LocaleMessages;
  ...
```

- 영어가 타입의 원본이다. `LocaleMessages`는 영어에서 유도한 "같은 키, 모두 문자열" 모양이다. 다른 언어의 네임스페이스 파일은 객체 리터럴에 `satisfies LocaleMessages['<ns>']`를 붙이므로 **키가 빠지거나 남으면 컴파일 오류**다.
- 영어 파일 몇 개는 키를 도메인 타입에 묶는다: `badges`(`PresetBadgeId`), `categories`(`ItemCategory`), `themes`(`ColorTheme`). 새 배지·카테고리·테마를 추가하면 영어 문자열이 없을 때 컴파일 오류가 난다.
- 새 네임스페이스: `locales/en/<ns>.ts`를 만들고 `locales/en/index.ts`에 등록한 뒤, 모든 언어에 같은 파일을 만들고 각 `index.ts`에 등록한다(빠지면 컴파일 오류와 `i18n:check`가 알려 준다). 번역은 `i18n:export` → 번역 → `i18n:import`로 채워도 된다(import가 없는 파일과 index를 만든다).
- 파일 형식 제약: 값은 문자열 리터럴(따옴표나 `${}` 없는 백틱), 키는 식별자나 문자열. 주석은 자유. 도구가 이 형식으로 쓰고 읽는다.

### 2.3 지연 로딩과 폴백

- 영어는 번들에 들어 있다. 나머지 언어는 `import.meta.glob('./locales/*/index.ts')`로 찾아 언어마다 별도 청크로 나뉜다(청크 파일 이름은 `chunks/index-<hash>.js`). `APP_LANGUAGES`에 없는 폴더(드래프트)는 로더를 만들지 않으므로 절대 불러오지 않는다.
- `setLanguage(lang)`: 메시지를 불러온 **뒤에** 언어를 바꾸고 구독자에게 알린다. 불러오는 동안에는 이전 언어가 그대로 보인다(반쯤 번역된 화면 없음). 이미 불러온 언어면 반환 전에 즉시 바꾼다. 호출이 겹치면 마지막 호출이 이긴다. 불러오기에 실패하면 오류를 기록하고 언어는 바꾸되 문자열은 영어로 보인다. 다음 호출 때 다시 시도한다. reject하지 않는다.
- `ensureLanguageLoaded(lang)`: 미리 불러오기. 동시에 호출해도 요청은 하나다.
- 사이드패널 시작(`entrypoints/sidepanel/startup.ts`): 저장된 언어(설정을 못 읽으면 감지한 언어)를 불러온 다음 첫 렌더를 한다. 첫 화면에 다른 언어가 번쩍이지 않는다.
- `t()`는 현재 언어에 키가 없거나 아직 불러오지 않았으면 **키별로** 영어를 쓴다. 영어에도 없으면 키 이름을 그대로 보여 준다(타입상 일어나지 않음).
- `state.ts`는 메시지 표를 import하지 않는다(카탈로그가 로더를 등록). 숫자·날짜 서식만 쓰는 모듈과 백그라운드 워커는 메시지 청크를 끌어오지 않는다.
- 테스트: `src/i18n/test-setup.ts`가 모든 언어를 미리 불러 두므로 테스트에서는 `setLanguage('ko')` 직후 바로 한국어가 나온다. 지연 로딩 자체는 `lazy-loading.test.ts`와 `startup.test.ts`가 가짜 로더로 검사한다. `vi.resetModules()`로 새 모듈을 쓰는 테스트는 `ensureLanguageLoaded`를 직접 불러야 한다.

크기(프로덕션 빌드, 2026-09-29): 사이드패널 청크 812,592 B → 708,752 B(gzip 253,977 B → 222,354 B). 언어 청크는 원본 22.6~31.2 kB, gzip 9.0~9.8 kB씩이다. 언어 하나를 추가하면 대략 이만큼의 청크와 달력 로케일 청크(원본 약 6 kB)가 생기고 사이드패널 청크는 거의 늘지 않는다(프랑스어 시험 추가 때 +0.27 kB).

### 2.4 복수형

- 개수에 따라 달라지는 문장은 `<key>_one`, `<key>_other`(필요하면 `_zero`/`_two`/`_few`/`_many`)로 나누고 `tn(ns, key, count, params?)`로 부른다. `Intl.PluralRules(intlLocale)`의 범주를 고르고, 그 형태가 없으면 `_other`를 쓴다. `{count}`는 자동으로 채운다.
- 모든 언어는 영어의 복수형 키(`_one`, `_other`)를 가진다. 구분이 없는 언어(ko, ja, zh-CN, zh-TW)는 두 키에 같은 문장을 넣는다.
- 영어에 없는 범주가 필요한 언어는 그 형태를 추가로 가진다. 타입은 복수형 키에 한해 `_zero/_two/_few/_many`를 선택적으로 허용한다. 예: 프랑스어는 `many`(1 000 000 등), 러시아어는 `few`·`many`. `i18n:export`가 그 언어에 필요한 형태를 번역 파일에 넣고, `i18n:check`는 빠지면 오류, 그 언어가 쓰지 않는 범주가 있어도 오류로 본다.
- 폴백: 현재 언어에 문장이 없어 영어를 쓰면 복수 규칙도 영어 규칙을 쓴다("1 booth").

### 2.5 자리표시자

- 앱 문자열은 `{name}` 형식이다. `tp(ns, key, { name })`와 `tn`이 채우고, 숫자는 현재 언어의 자릿수 구분으로 서식한다. 값이 없는 자리표시자는 그대로 남는다.
- 번역은 영어와 **같은 자리표시자를 같은 개수만큼** 가져야 한다(순서는 자유). 완전성 테스트, `i18n:check`, `i18n:import`가 같은 규칙으로 검사한다.
- Chrome `_locales` 문자열의 자리표시자는 `$NAME$` 형식이다(지금은 없음). 도구는 두 형식을 따로 검사한다.

### 2.6 Chrome `_locales`

- 확장 이름(`appName`), 설명(`appDescription`), 우클릭 메뉴, 단축키 설명은 `chrome.i18n`이 `public/_locales/<chromeLocale>/messages.json`에서 읽는다. manifest의 `default_locale`은 `en`이다.
- 켜진 언어마다 폴더가 있어야 하고 키는 영어와 정확히 같아야 한다(`chrome-locales.test.ts`, `i18n:check`). 켜진 언어나 드래프트가 쓰지 않는 폴더는 오류다.
- 폴더 이름은 Chrome이 지원하는 코드여야 한다(`zh_CN`처럼 밑줄). 목록: <https://developer.chrome.com/docs/extensions/reference/api/i18n#locales>. 지원하지 않는 코드는 Chrome이 무시한다. `i18n:new`가 이 목록으로 확인한다.

## 3. 도구 (`scripts/i18n`, Node ESM, 추가 의존성 없음)

| 명령 | 하는 일 |
|---|---|
| `pnpm i18n:export <lang> [--out file]` | 번역 파일(JSON)을 만든다. 없으면 표준 출력 |
| `pnpm i18n:import <lang> <file> [--dry-run]` | 번역 파일을 로케일 파일과 `_locales`에 반영 |
| `pnpm i18n:check` | 켜진 언어 전부 검사, 문제가 있으면 exit 1 (CI에서 `pnpm test` 다음에 실행) |
| `pnpm i18n:new <lang> [옵션]` | 새 언어를 드래프트로 시작 |

번역 파일 형식(사람과 LLM 모두 대상):

```json
{
  "lang": "ja",
  "source": "en",
  "instructions": "Translate each \"en\" text into Japanese ...",
  "keys": {
    "aiConnect.defaultModel": { "en": "Default: {model}", "current": "既定のモデル: {model}", "placeholders": ["model"] },
    "events.boothCount_one": { "en": "{count} booth", "current": null, "placeholders": ["count"] },
    "_locales.appName": { "en": "Acorn Collector", "current": "どんぐりポケット", "placeholders": [], "description": "..." }
  }
}
```

- `current`가 `null`이면 미번역이다. 영어에 없는 복수형에는 `note`, Chrome 키에는 `description`이 붙는다.
- `i18n:import`는 기존 파일을 **바뀐 값만** 제자리에서 고친다(주석·순서 유지). 없는 키는 영어 순서에 맞춰 넣고, 없는 파일과 `index.ts`는 만든다. 쓴 파일은 prettier로 정리한다.
- 다음 경우 **아무 파일도 쓰지 않고 거부**한다: 자리표시자가 다름, 영어에 없는 키, 그 언어가 쓰지 않는 복수 범주, 결과에 여전히 미번역이 남음, 다른 언어의 파일. export 뒤 영어 원문이 바뀐 키는 경고로 알려 준다.
- 바꾸지 않은 export를 다시 import하면 아무것도 쓰지 않는다(모든 언어에 대해 바이트 단위로 테스트).

## 4. 언어 추가 4단계

프랑스어(`fr`)를 예로 든다. 이 흐름은 ACORN-9 작업 중 워크트리에서 실제로 끝까지 실행해 보고 되돌렸다.

1. **드래프트 시작**
   ```sh
   pnpm i18n:new fr --currency EUR --intl fr-FR
   ```
   `languages.ts`의 `DRAFT_LANGUAGE_INFO`에 항목이 추가되고(이름은 `Intl.DisplayNames`, Chrome·달력 로케일은 자동 확인. 옵션 `--native`, `--english`, `--chrome`, `--day-picker`로 바꿀 수 있음), `src/i18n/locales/fr/translation.json`(모든 `current`가 `null`)이 생긴다. 항목을 검토한다. 이 단계에서는 `public/_locales/fr`를 만들지 **않는다**: 그 폴더는 그대로 출시되고 Chrome은 폴더마다 완전한 `messages.json`을 기대하므로, 번역이 끝난 뒤 import가 만든다.
2. **번역**: `translation.json`의 `current`를 모두 채운다(사람 또는 LLM. 파일의 `instructions`를 그대로 LLM에 주면 된다). 진행 상황은 `pnpm i18n:check`가 note로 보여 준다(드래프트는 CI를 실패시키지 않는다).
3. **가져오기**
   ```sh
   pnpm i18n:import fr src/i18n/locales/fr/translation.json
   ```
   `locales/fr/*.ts`, `locales/fr/index.ts`, `public/_locales/fr/messages.json`이 생긴다. 미번역이나 자리표시자 오류가 있으면 거부하고 목록을 보여 준다. 이 시점에도 fr은 드래프트라 앱에 나오지 않는다(빌드에 청크는 생기지만 로드되지 않는다).
4. **켜고 검사**
   - `DRAFT_LANGUAGE_INFO`의 항목을 `LANGUAGE_INFO`로 옮기고 `APP_LANGUAGES`에 `'fr'`을 넣는다. `translation.json`은 지운다.
   - `dayPickerLocale`이 새 값이면 `components/ui/day-picker-locales.ts`에 한 줄 추가한다(빠지면 컴파일 오류).
   - `languages.test.ts`의 출시 언어 목록(소유자 결정을 일부러 고정한 유일한 테스트)을 고친다.
   - `pnpm i18n:check && pnpm typecheck && pnpm lint && pnpm test && pnpm build`. 언어별 테스트(완전성, `_locales`, 서식, AI 프롬프트, 달력)는 새 언어로 자동 확장된다.
   - 출시 전: 스토어 등록 문구(아래 6절)와 스폰서 피드(아래) 확인.

스폰서 피드(`sponsors/feed.json`): 광고의 `locales`에 앱이 모르는 코드가 하나라도 있으면 그 광고 전체를 건너뛴다. 이전 버전 사용자는 새 코드를 모르므로, 새 언어용 광고는 **그 언어만 담은 별도 광고**로 만든다.

## 5. RTL(오른쪽→왼쪽) 언어

아직 지원하지 않는다(아랍어·히브리어·페르시아어 등). 추가하려면:

- `LanguageInfo`에 `direction: 'ltr' | 'rtl'`을 추가하고, `App.tsx`가 `<html lang>`과 함께 `<html dir>`을 설정한다.
- 스타일을 논리 속성으로 바꾼다. `ml-*/mr-*/pl-*/pr-*/left-*/right-*/text-left` → `ms-*/me-*/ps-*/pe-*/start-*/end-*/text-start`. 절대 위치(예: DatePicker 팝오버의 `left-0`, 뱃지의 `-right-1.5`)와 좌우 화살표 아이콘(뒤로 가기, 달력 이전/다음)은 방향에 따라 뒤집는다.
- 캡처한 원문·상품명처럼 방향이 섞인 텍스트는 `dir="auto"` 또는 `<bdi>`로 감싼다.
- react-day-picker는 `dir` 속성을 지원한다. 달력에 넘겨야 한다.
- 스크린샷 검토와, 방향 의존 클래스를 막는 린트 규칙(또는 테스트)을 추가한다.

## 6. 스토어 등록

- 스토어 목록의 확장 이름·짧은 설명은 `_locales/<chromeLocale>/messages.json`의 `appName`·`appDescription`에서 온다. 번역 파일의 `_locales.appName`·`_locales.appDescription`이 그 값이다. 짧은 설명은 스토어 제한(132자)을 넘지 않게 한다.
- 상세 설명·스크린샷은 Chrome 웹 스토어 개발자 대시보드에서 언어별로 따로 입력한다. 문구 원본은 `docs/STORE_LISTING.md`에 언어별로 추가하고, 광고 고지 문장을 첫 부분에 둔다(그 문서의 규칙). 지원 언어 목록 문장("한국어·English·日本語·简体中文·繁體中文 지원")도 모든 언어의 설명에서 고친다.
- 스크린샷은 새 언어로 찍는다(아래처럼 하네스의 `locale` 옵션 사용).

## 7. 알려진 한계

- 언어 청크 파일 이름이 모두 `index-<hash>.js`라 네트워크 탭에서 언어를 바로 알아보기 어렵다.
- 번역 파일 파서는 위 형식만 읽는다. 로케일 파일에서 문자열을 계산하거나 다른 모듈을 import하면 도구가 오류를 낸다(의도된 제약).
- `useLanguage()`는 언어가 **바뀔 때만** 다시 렌더링한다. 같은 언어의 메시지가 첫 렌더 뒤에 도착하는 경우는 시작 코드가 먼저 불러오는 것으로 막는다. 새 진입점을 만들 때도 첫 렌더 전에 `loadStartupSettings()` 또는 `ensureLanguageLoaded()`를 기다린다.
- 자리표시자 개수까지 같아야 한다는 규칙은 엄격하다. 한 번만 써도 자연스러운 언어라도 영어가 두 번 쓰면 두 번 넣어야 한다.
